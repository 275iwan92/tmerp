Aturan Layar TMERP

Aturan baku per jenis layar: grid, form dokumen, dan seterusnya. Setiap bagian punya teks prompt siap salin untuk sesi Claude, jadi aturan yang sama dipakai di semua layar tanpa diulang dari awal.

Disusun 26 September 2026 dari standar yang sudah berjalan (docs/md_for_systems/griduistandard.md, objek DevLib x-dl::grid / x-dl::master) dan arahan Johannes Iwan hari ini. Pendamping Pegangan Fase TMERP.

Cara pakai

  • Bagian bertanda Untuk dibaca sudah berlaku di kode, menunggu Anda baca dan koreksi.
  • Bagian bertanda Draf belum dikunci. Masih ada keputusan terbuka.
  • Setelah Anda setuju, tanda berubah jadi Dikunci. Prompt di bagian itu lalu dipakai apa adanya di setiap sesi.
  • Perubahan aturan cukup dilakukan di halaman ini. Sesi Claude berikutnya membaca dari sini.

Grid

Untuk dibaca

Grid adalah daftar data yang dibuka dari menu: daftar Customer, Mesin, Quotation, Customer Order, dan seterusnya. Semua grid memakai tampilan yang sama. Yang berbeda hanya isi toolbar dan kolom Aksi, tergantung jenisnya.

Aturan inti (berlaku di semua grid)

  • Tanpa judul halamanNama layar sudah tampil di tab/menu. Grid langsung mulai dari kotak statistik.
  • Kotak statistik pastel = filterMaksimal 5 per baris, 5 warna baku (Total biru, Baik hijau, Perhatian kuning, Kritis merah, Tambahan ungu). Klik kotak = grid tersaring, klik lagi = lepas. Angka di kotak tetap menghitung keseluruhan. Kotak Total dan kotak rupiah tidak bisa diklik.
  • Kolom identitasSatu kolom paling kiri: avatar inisial + Nama (tebal) + Kode (kecil, abu). Bukan kolom Kode dan Nama terpisah. Kalau tidak ada kode, jangan dikarang.
  • Klik 2x = bukaSatu-satunya cara membuka form dari baris, selain ikon Edit/Buka. Tidak ada kolom radio/checkbox pilih baris.
  • Ikon Aksi berbingkai (Pilihan C)Font Awesome dalam kotak: Edit fa-pen, Buka fa-up-right-from-square, Confirm fa-check, Batal fa-xmark, Lihat fa-eye. Tanpa teks, ada tooltip. Toggle Aktif/Nonaktif ikon & warnanya diatur komponen. Setiap aksi yang mengubah data minta konfirmasi dulu.
  • Toolbar minimalHanya kotak cari dan + New Record (tulisan persis, navy, paling kanan). Dilarang: dropdown filter, checkbox, tombol yang butuh "baris terpilih", tombol Hapus.
  • Badge statusStatus dokumen (Draft, Published, Confirmed…) memakai 5 warna pastel yang sama, dipetakan per status. Tidak membuat warna baru.
  • Intip detail (dokumen ber-item)Panah di kiri baris membuka tabel item di tempat, hanya baca. Klik panah tidak membuka form.
  • Paginasi ala ScriptCaseKiri: Go to halaman + View 10/25/50/100. Tengah: nomor halaman. Kanan: rentang dari total. Default 25 baris.
  • PerformaPaginasi dan penyaringan di server (bukan muat semua lalu saring). Relasi lintas database dicari bertahap, bukan whereHas bertingkat.

Prompt Grid untuk sesi Claude
Bangun/ubah GRID di TMERP mengikuti "Aturan Layar TMERP" bagian Grid.
Acuan detail: docs/md_for_systems/griduistandard.md. Layar v2: objek x-dl::grid
(actions = master | worklist | none, openUrl untuk klik 2x/Edit/Buka).

Tentukan dulu jenisnya:
- MASTER: toolbar = cari + "+ New Record". Aksi = Edit, lalu Aktif/Nonaktif.
- TRANSAKSI/WORKLIST: Aksi = Buka (selalu) + Confirm (hanya baris Draft yang ada isinya).
  "+ New Record" hanya bila dokumen lahir dari grid ini; bila lahir di layar lain,
  toolbar = cari saja + satu baris catatan asal dokumen.

Wajib di semua grid:
1. Tanpa judul halaman; mulai dari kotak statistik.
2. Kotak statistik pastel (5 warna baku, maks. 5/baris) = filter klik/lepas.
   Angka kotak = keseluruhan. Klausa filter = klausa hitung angkanya.
3. Kolom identitas paling kiri: avatar + Nama tebal + Kode kecil. Jangan mengarang kode.
4. Klik 2x baris = buka form. Form Edit SAMA dengan form New (satu layar, satu bentuk).
5. Ikon Aksi Font Awesome berbingkai lewat komponen (x-grid.action-icon / x-dl::grid),
   tanpa teks, ada tooltip, aksi pengubah data minta konfirmasi.
6. Toolbar HANYA cari + "+ New Record". Dilarang dropdown filter, checkbox,
   tombol butuh-baris-terpilih, tombol Hapus.
7. Badge status pakai 5 warna pastel yang sama. Dokumen ber-item: panah intip detail
   (baca saja). Paginasi ala ScriptCase, default 25.
8. Paginasi & saring di server. Relasi lintas database: query terpisah, cocokkan di PHP.
Fitur opsional (Kolom/Sort/Export, Filters, centang massal, Kartu) HANYA bila user minta.
Teks UI lewat Translator::t(). Setelah ubah class Tailwind: npm run build.
Verifikasi ke database dummy (ddt*), lalu commit + push per potongan kerja.

Form dokumen (master-detail)

Draf

Form satu dokumen dengan bagian kepala (header) dan daftar item di bawahnya: Quotation, Customer Order, PR, PO, dan seterusnya. Arahan 26 September: New dan Edit adalah form yang sama, dan tombolnya baku mengikuti status dokumen.

  • Preview cetak = panel dari kiri Dikunci 26 SepTombol Preview Cetak membuka halaman cetak sebagai panel yang meluncur dari kiri di atas form (bukan tab baru, menu tetap utuh). Tutup dengan tombol Tutup, Esc, atau klik area gelap, dan panel langsung hilang. Cetak/PDF dan pilihan kop PPN tetap di bar cetak dalam panel. Contoh: Quotation.

Setelah keputusan di bawah dijawab, bagian ini diberi mockup dan prompt siap salin seperti bagian Grid, lalu dibuat sekali sebagai objek DevLib yang dipakai semua form dokumen. Quotation menjadi layar pertama.

Untuk didiskusikan

  1. Cancel sesudah confirmed: membatalkan dokumen (status Cancelled, wajib isi alasan, sesuai kolom stat_cancel + cancel_reason), bukan sekadar menutup layar?
  2. Delete sebelum confirmed: dokumen dihapus permanen dari database, atau hanya ditandai terhapus?
  3. Print sebelum confirmed: disembunyikan sama sekali, atau tampil abu-abu dengan keterangan “Confirm dulu untuk cetak”?
  4. Customer Order & Delivery Order: “+ New Record” ikut langsung membuka form (customer dipilih di form), seperti Quotation sekarang?
