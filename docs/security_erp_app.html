Security ERP App

Ketentuan hak akses aplikasi: setiap user punya satu level dan ikut satu atau lebih group; group menentukan hak di tiap modul, level menentukan siapa yang boleh approve atau reject dokumen.

Disepakati bersama Johannes Iwan, 28 September 2026. Menggantikan grup lama yang dinamai jabatan (DIREKSI, MGR_SALES, dst.). Jabatan tetap hanya ada di struktur organisasi.

Aturan gabungan

Disepakati
  • Hak tertinggi yang berlakuUser di beberapa group mendapat hak tertinggi dari group-group itu per modul. Contoh: nisa ikut group Sales dan Produksi, jadi keduanya bisa dibuka.
  • Sub-module mewarisi modulKecuali diatur khusus, sub-module memakai hak modulnya. Pengaturan khusus boleh lebih rendah atau lebih tinggi.
  • Tanpa group = tanpa modulDefault tolak. User yang belum ikut group mana pun hanya melihat halaman awal dan profilnya.
  • Nama group bukan jabatanGroup dinamai menurut area kerja (Sales, Costing, HR). Jabatan hanya di struktur organisasi.

Prompt untuk sesi Claude

Ketentuan Security ERP App
Ikuti "Security ERP App" TMERP:
- User punya 1 level dan ikut 1..n group. Group = area kerja per modul, JANGAN dinamai jabatan.
- Hak group x modul/sub-modul: RO, ROP, RW, RWP, RWPE (lihat / print / tulis / export).
  Sub-modul mewarisi modul kecuali diatur. Beberapa group = hak tertinggi. Tanpa group = tolak.
- Level (1..7): data-entry, supervisor, vice-manager, manager, general-manager, director,
  president-director. Level HANYA untuk approve/reject alur dokumen (level >= tahap + hak RW).
- Peran global: super-admin (semua + pengaturan kritis; dipakai UAT), admin-app (semua modul RWPE sebagai
  pemeriksa + kelola user, tanpa pengaturan kritis), developer (F10, Data Dictionary).
- Back to Draft: hanya super-admin, admin-app, level manager ke atas.
- Pemeriksa tidak input: admin-app & level manager ke atas TIDAK bisa Save/Delete/Confirm/New di form
  data/dokumen (isi terkunci); tetap Approve/Reject/Cancel/Back to Draft/Print/Email/Export.
  Kecuali super-admin (UAT). Layar pengaturan & kelola user tidak terkena.
- Penegakan di komponen form/grid standar: RO/ROP kunci field & sembunyikan Save/Delete/Confirm/New;
  Print hanya ROP/RWP/RWPE; Export hanya RWPE; Approve/Reject sesuai level tahap.
- Profil user di menu: nama lengkap saja. Jabatan hanya di struktur organisasi.

Keputusan terbuka

Draf
  1. Sumber level. Level diambil otomatis dari jabatan di struktur organisasi, dengan penimpaan per user bila perlu?
  2. Penerima approval. Dikirim ke atasan langsung lebih dulu, atau ke siapa pun yang levelnya cukup di modul itu?
  3. ROPE. Perlu hak lihat + print + export tanpa tulis (untuk direksi atau auditor), atau lima hak di atas cukup?
  4. Tahap approval awal. Isian contoh per dokumen di bagian Approval alur dokumen dipakai sebagai titik awal?
  5. Daftar group awal. Satu group per modul (Sales, Costing, Product Development, Produksi, Pembelian, Inventory, Keuangan, HR, Laporan Manajemen), ditambah group khusus bila perlu?
