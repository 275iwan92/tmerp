## Relations
- **source**: a POSTED receipt and its rejected quantities (`../receive/10_card_purchase-receive.md`), the material master, the supplier (`../order/12_card_supplier-and-category.md`).
- **used_by**: the receipt cancel guard, the Stock Inspection report, the Approval Center, the Purchase Return grid.
- **flows**: DRAFT -> SUBMITTED -> CONFIRMED -> COMPLETED (manual); nothing flows to stock or finance.
- **frozen_zone**: the Goods Receipt / GR-IR flow is frozen; an automatic Stock Out and journal on approval would change it, so it needs Jo's decision (backlog item "Purchase Return v2, dibahas di sesi lain").

## Findings (recorded, not fixed)
1. **Approval of a return moves nothing.** No stock out, no GR/IR reversal, no PO or receipt update. The "rejected, still to return" quantity of the Stock Inspection report never falls, because `pv_line.c_qty_returned` is never written; and the PO line stays RECEIVED although part of the delivery was rejected (receipt card finding 1). The replacement columns (`replacement_*`) are never written either. FACT.
2. **RESOLVED 2026-10-19 (Master T6, Jo): Notes / Chronology**: the v1 box wrote to a column that did not exist and the text was dropped; v2 stores it in the new column `prt_return.i_notes`.
3. **RESOLVED 2026-10-19 (Master T6, Jo) for receipt returns**: Return qty cannot exceed the remaining rejected quantity (and a Rejected or Cancelled return frees its quantity again). Returns from stock still have no cap against the stock on hand (only qty > 0 and price > 0). FACT.
4. **RESOLVED 2026-10-19 (Master T6)**: the Start step re-checks that the receipt is POSTED and still has a returnable balance, and the save re-checks it again. FACT (`PurchaseReturnService::save`, `routes/v2_purchase_return.php`).
5. **Cancel only in DRAFT** (unchanged); a SUBMITTED or CONFIRMED return cannot be withdrawn, and a REJECTED one is final, but v2 offers Duplicate on Rejected and Cancelled returns so the document can be corrected as a new draft. FACT.
6. **Three vocabularies** (PR/PO APPROVED, return CONFIRMED / COMPLETED, receipt POSTED). FACT.
7. **Tests added, still no data**: `tests/Feature/PurchaseReturnServiceTest.php` (rolled-back transactions, 5 tests) now covers both sources, the quantity cap, Submit, Hold, Reject, Approve, Complete, Cancel, Duplicate, the Approval Center and the screens; `prt_return` / `prt_line` still have no rows in the mockup or live data. FACT.
