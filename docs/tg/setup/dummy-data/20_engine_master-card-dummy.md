## Level rule (what level a product gets)
1. `skipReason` (`:242-249`) first: "already exists, skipped" (see Idempotency), or "card incomplete: ..." when `missing` (`:284-296`) finds no artwork, no P x L x T (all three), no knife width, or no material on any card of the product.
2. Otherwise `one` (`:252-272`) takes the FIRST level in the order `inquiry, prodev, procost, co, product` whose quota is above 0 and subtracts 1 (line 257-261). No level left: "level quota used up, skipped".
3. Products are processed in file order (`glob` order = by name). The quota is spent in the order of the levels, not matched to a product by name. Example (FACT, `MasterCardDummyEngine.php:257`): quota `inquiry:1,prodev:1` and three ready products -> product 1 = inquiry, product 2 = prodev, product 3 = skipped.
4. The quota is subtracted BEFORE the product is built (line 261): a product that then fails validation still consumes its slot (Finding 4).

## Flow (text twin; diagram not made yet)
1. Read the PDF folder: `groups` -> `assertDummy` -> `MasterCardPdfReader::read` for every `*.pdf`; group key = design number, else item code, else file name (`:140-150`).
2. For each product: `skipReason`; if blocked, the report row gets the reason and the loop continues.
3. Pick the level from the quota (rule above).
4. Level product: `cards` + `makeProduct` + copy flat size, and stop.
5. Other levels: `cards` (a Collection card per PDF with SOURCE and ARTWORK files, customer ensured) -> `makeInquiry` (DRAFT Inquiry, one tier) -> `shapeParts` -> `InquiryWriter::confirm`.
6. If level is at least prodev: open in ProDev, save and confirm the layout of every component from the card (canvas = print size, knife pieces = UP, press and plano from the card text; `method=CARD`), then `syncProdev`.
7. If level is at least procost: fixed-input costing, calculate, publish, `syncProcost`.
8. If level is co: Quotation create, confirm (publish), WIN, then pick qty, set due date and PO, Confirm CO, approve until CONFIRMED (error if still not CONFIRMED after 6 rounds, `:473-478`).
9. Add the row to the report (design, name, level, inquiry number or reason).

## Idempotency
`exists` (`:274-281`): a product is skipped when (a) an ACTIVE `prod_product` has the same `design_no` or `product_code` = card code (`MasterCardService::existingProduct`, line 234), or (b) any card with status INQUIRY or PRODUCT has the same design number or card code. A card built at level inquiry gets status INQUIRY (`MasterCardService.php:296`), so a second run skips it. Cards with status READY / INCOMPLETE do not block. Re-importing the same card code + design no + part label updates the old card row while it is not converted (`MasterCardService.php:73-76`). Nothing is overwritten.
Today (FACT, `plan()` run): all 8 products answer "already exists, skipped", so a new `run` would build nothing.

## Edge cases
- Product with neither design number nor item code: the group key falls back to the file name, and `exists` has an empty condition (Finding 3).
- A Part card without height or knife is incomplete (`missing`); the three Buku Pedoman PDFs have no `dim_h` and no knife width (checked with the reader today) and are only "already exists" because the check runs first.
- `ValidationException` inside one product (from the services) is caught per product and written as "incomplete: ..." (`:127-129`); any other exception (RuntimeException, DB error) is NOT caught in `run`, stops the whole run, and leaves the products already built plus the half-built one. The route catches `Throwable` and shows the message (`v2_dummy_mastercard.php:60-62`).
- Customer text starting with "nama pelanggan" or empty gives no customer (`:346`).
- Layout: no matching plano gives `planoId` NULL; no press match gives Komori GL440; unknown press name in `prod_machine` throws (`:440`).
- Run time: about 20 seconds per product (text in the screen confirm dialog, FROM DOCUMENT in the view, not timed).
