# Concept card: Stock Document (Stock In, Stock Out, Return, Adjustment/Opname, Reversal)

> Written 2026-10-16 (group Inventory/Stock). FACT = mockup DB (`ddtinv`, `ddtsys`, `ddtmst`, read through the `tm2*` connection by schema prefix) and code with line numbers, seen this session. No test was run (this task allowed no DB writes); test names are only cited as existing.
> Verified: 2026-10-18

- **Document type**: concept card. **Module/sub-module**: Inventory > Stock > Raw Material / Finished Goods / Semi Finished Goods (menu groups `INV_TRX_RM`, `INV_TRX_FG`, `INV_TRX_SFG`; FACT `sys_app_menu`: each has Stock In, Stock Out, Return from Production, Stock Adjustment & Physical Count, Adjustment Approval, and a Report group).
- **Canonical name**: Stock Document = one header row + line rows in the table pair of its class: RM `rm_stock` + `rm_stock_d`, FG `fg_stock` + `fg_stock_d`, SFG `sfg_stock` + `sfg_stock_d` (database `tm2inv`; `ddtinv` in the mockup). One screen family and one engine serve all three classes.
- **Synonyms**: Stock In, Penerimaan / Bukti Barang Masuk, Stock Out, Bukti Barang Keluar, issue, Return from Production, RTP, Adjustment, Opname (Stock Opname, Physical Count), BB (Saldo Awal, opening balance), Reversal (pembalik), `doc_cat`.
- **NOT the same as**: Stock Card row (`rm_stockcard` is the RESULT of posting, card `11_card_stock-card-and-balance.md`); Stock Transfer (`inv_transfer`, its own document, Warehouse side); Goods Receipt / SPB (`pv_receipt`, Procurement, which CREATES a Stock In document through the same engine); Delivery Order (does not touch stock, see Findings).

## Relations
- **source**: Master items (`mat_raw`, `prod_product`, `prod_part`), warehouse bins (`wh_loc`), Goods Receipt (`pv_receipt`), Pick List, Count Task, Subcon issue.
- **used_by**: the posting engine (card `20_engine_stock-posting.md`) writes `rm_stockcard` / `fg_stockcard` / `sfg_stockcard`; Stock Return reads POSTED Stock Out lines and increases their `qty_returned` at posting; reports (card `18_card_stock-reports.md`).
- **flows**: Draft saved by `StockDocumentService::saveDraft` -> post (`StockPostingService::postDocument`) -> card rows -> on-hand view. Cancel after posting = `StockReversalService` (card `22_engine_stock-reversal.md`).
- **frozen_zone**: not in the Sales frozen list; Stock Card and the Stock Summary report are "already correct, do not change" per Jo (rule A.26 in `docs/globaluserrules.md`).

## Findings (recorded, not fixed)
1. **Stuck rows**: 28 RM and 1 FG header are `flow_status`=DRAFT with `stat_confirm`=1 and no `posted_at`; the grid shows them as Draft, but the form opens read-only and `postDocument` answers "already posted". They cannot be posted, edited or cancelled from the screen. FACT (query, 28 + 1 rows).
2. **No Cancelled/Closed in data**: 0 headers with `stat_cancel`=1; `stat_closed` is never written. The "Draft/Confirmed/Cancelled/Closed" lifecycle of the UI rule is not what stock documents use (they use `flow_status`). FACT.
3. **FG has no automatic movement**: the only code that writes `fg_stock` / `fg_stockcard` is the manual Stock In/Adjustment forms and the count task. Delivery Order never reduces FG stock, and production output never adds it (grep of `app/` for `FgStock`, `FgStockcard`). The v1 comment says FG leaves "through Delivery Order, not built yet"; the Delivery Order exists now (`docs/tg/sales/delivery/10_card_delivery-order.md`) and writes no stock. FACT (grep).
4. **Document number without lock**: `nextDocNo` reads the highest number outside any lock; two clerks saving at the same moment get the same number and the second save hits the UNIQUE key on `doc_no`. FROM CODE, not reproduced.
5. **Mixed numbering in data**: 20+ legacy forms and `-DUPn` suffixes next to `IN/26/00001`; the new numbering is clean only for documents created by the current screens. FACT (group-by query).
6. **`period_id` never filled**: `rm_stockcard.period_id` is NULL in 208 of 208 rows; headers copy `period_id` from the header, which no code sets. Period control works through the document DATE (`InvPeriod::closedThrough`), not through this column. FACT.
7. **Button wording**: the v1 forms say "Simpan Draft", "Konfirmasi & Posting", "Batalkan", "Ajukan Persetujuan", "Setujui", "Tolak" (English twins "Save Draft", "Confirm & Post" in the translation table); the UI rule requires English document buttons (New, Save, Confirm, Cancel...). the v1 Return page had the labels hard-coded in Indonesian. FACT (grep). Update 2026-10-19: Stock In, Stock Out and Return are now the v2 form with English buttons (Save, Confirm, Cancel, Duplicate); Adjustment and Opname are on the v2 form too (Save, Submit, Cancel, Duplicate).
8. **Seeded settings that no code reads**: `INV_ALLOW_NEGATIVE`, `INV_BACKDATE_DAYS`, `INV_ADJ_LIMIT_L1`, `INV_ADJ_LIMIT_L2`, `INV_DEFAULT_COSTING`, `INV_REASON_ADJ`, `INV_REASON_RTP` exist in `sys_constant` (migration `2026_08_21_000010_create_inv_tier3_delta_and_new_tables.php`) but appear in no file under `app/`, `resources/`, `routes/`. Negative stock is always refused, the back-date window is not enforced (an RM document dated 2016-01-01 exists), the adjustment reasons are a fixed list in the Blade. FACT (grep).
