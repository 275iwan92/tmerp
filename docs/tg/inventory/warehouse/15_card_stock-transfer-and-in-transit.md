# Concept card: Stock Transfer, Approval Center and In Transit

> Written 2026-10-16 (group Inventory-Warehouse). Verified: 2026-10-16. FACT = mockup DB (`ddt*` through `tm2*`, `--env=mockup`) and code with line numbers, seen this session. FROM DOCUMENT = not checked. Tests were NOT run (brief: no DB writes); test names are read from the files.

- **Document type**: concept card (numbered document that moves stock between bins/buildings). **Module/sub-module**: Inventory > Stock > Stock Transfer (`INV_TRF_DOC` group under `INV_STOCK`: Stock Transfer `v2:stock-transfer`, Stock Transfer Approval Center `v2:approval-tf`) and Warehouse > Transfer > In Transit (`WH_TRF`, `INV_WH_TRANSIT` `v2:wh-in-transit`; FACT `sys_app_menu`). The document belongs to Inventory, field work to Warehouse (rule A.26, FROM DOCUMENT).
- **Canonical name**: Stock Transfer = `tm2inv.inv_transfer` (header, number `TF` + yy + 5 digits, born at Confirm) + `inv_transfer_line` (one item from one source bin to one destination bin). Two modes: DIRECT (`transit_mode`, one step) and TWO_STEP (Ship, then Receive through the virtual In Transit bin).
- **Synonyms**: pindah stok, mutasi, transfer antar bin / antar gudang, TF, in transit, kirim-terima, Ship/Receive, discrepancy (selisih).
- **NOT the same as**: Putaway (it creates one real transfer, card `12_card_receiving-and-putaway.md`), Delivery Order (customer), Stock Adjustment/Opname (changes total stock; a transfer never changes the item total), Subcontract Send (also done as a transfer to a vendor bin, Batch/Subcon group).

## Relations
- **source**: stock cards (`rm_stockcard`, `sfg_stockcard`, `fg_stockcard`), pallets, bins and area rules (card `10_card_location-hierarchy.md`), module TF in `flow_config`.
- **used_by**: Putaway confirm, Pallet relabel (move remainder), Subcontract Send, Warehouse Map, Scan Track, Task Board (two-step transfers in progress), Print `stock-transfer` (`StockTransferPrint`).
- **flows**: Draft -> Confirm (DIRECT: stock moves, number born) or Confirm = Ship (TWO_STEP) -> Receive -> (Discrepancy -> Loss / Return) -> Closed; with approval: Draft -> Submitted -> Approved -> Confirmed.
- **frozen_zone**: stock-card writing belongs to the Stock group (`StockCardChain`); this service is the only writer of transfer rows. Do not change.

## Findings (recorded, not fixed)
1. **Test residue**: 11 of 15 dummy transfers (TF2600004-14) point to bins that were deleted; they keep their numbers and confirmed status, and their stock card rows (not checked) may refer to missing bins. FACT.
2. **Cancel does not re-run the Confirm checks**: it moves the stock back even if the source bin is now blocked, locked for counting, or its area is One-item/One-batch and now holds something else. FROM CODE (`StockTransferService.php:173-207` never calls `confirmErrors`).
3. **Receive checks the count lock on the original SOURCE bin too** (`BinRules::countLockViolations` looks at both `from_location_id` and `to_location_id`), so a shipment cannot be received while its source bin is locked for counting although the stock is in In Transit. FROM CODE (`StockTransferService.php:265`).
4. **Entry points treat approval differently**: putaway posts directly (`post()`), two-step transfers skip module TF, while a manual transfer and the pallet relabel move go through `confirm()` and therefore wait for approval when TF is on (the relabel move then ends as "waits for approval" although the label has already changed). FROM CODE (`WarehouseTaskService.php:25`, `StockTransferService.php:209-214`, `app/Support/V2/Data/Pallets.php:122-145`). Subcontract Send was not checked.
5. **Draft keeps no destination for an unrelated building**: a destination bin outside the chosen destination building is silently cleared on Save (`StockTransfer::save` sets `to_location_id` to NULL), and the user learns only at Confirm ("choose the destination bin"). FROM CODE (`StockTransfer.php:171,196-197`).
6. **Cancelled two-step in SHIPPED** is possible, in DISCREPANCY not (message says "after it was received"); the unsettled shortage in In Transit can only be settled by Loss or Return. FACT, `StockTransferService.php:184-190`.
7. **Approval amount is 0 for stock without a price** (qty x average price of the source bin, 0 when unpriced, e.g. customer-owned material). Whether a level matches an amount of 0 depends on the levels configured; not checked. FROM CODE (`StockTransferService.php:149-154`).
