# Sub-module: Product Costing (Pro-Cost)

> The sub-module page only summarizes and links; table/column facts are in the cards. Updated 2026-10-16 (Phase 2).

- **Module**: Sales > Inquiry & Quotation > Pro-Cost. Menu (FACT, `sys_app_menu` mockup): Pro-Cost New, Revise, Recalc, Instant (`v2:sales-procost*`).
- **Purpose**: calculate HPP and selling price per qty tier from Inquiry + ProDev; costing is confidential (A.8-A.9), publish = declassification to Sales.
- **Frozen zone**: ProCost flow/data. Read: `docs/claude_vital_flows.md`, `docs/ENGINE-ATTENTION.md`.

## Relations
- **source**: Inquiry Product (BOM, part, `stat_confirm_sales`), ProDev (layout, BOP waste, `stat_confirm_prodev`), rate masters (`prod_part_template`, `mat_grammage`), COSTING constants.
- **used_by**: Quotation (published price, must be integrated A.1), then Customer Order.
- **flags**: `stat_confirm_procost` in `iqp_inquiry` (A.20).

Notes for debugging
- Transactions: only Calculate has one. `CostingEngine::run` writes parts, coatings, header and every tier inside ONE tm2sdi transaction (`app/Services/Costing/CostingEngine.php:40-61`), so an engine error (unknown part type, discount outside the supplier limit) rolls all of that back; the error is caught in `CostingEntryService::hitung()` (`app/Services/Costing/CostingEntryService.php:427-438`) and shown as the engine error on the screen, and `learn` is skipped because it sits after `run` in the same try block. Everything else (mount, all edits, Advisor `fill`, Submit, Publish, Add to Quotation, Delete on Instant) has NO transaction: `fill` saves the model first and the `iqp_costing_recommendation` row second (`app/Services/Costing/CostingAdvisor.php:160-168`), so a crash between them leaves a value without its marker. Reverse uses two connections and commits tm2mst first (`app/Services/Costing/ReverseCostingService.php:187-188`); rows created in tm2mst stay if the tm2sdi commit then fails (also in the Reverse card).
- Opening creates data: a normal open of a worklist row runs `CostingEntryService::open()` (`app/Services/Costing/CostingEntryService.php:91-141`), which firstOrCreates the `iqp_costing` row (unique index on `inquiry_id`), copies the Inquiry tiers into `iqp_costing_price_tier` (one default tier when the Inquiry has none), creates one `iqp_costing_part` per Inquiry part that already has a ProDev layout, and runs the Advisor, all without any Save click. Only `?view=1` avoids this (`ProCost::state` viewOnly). The `iqp_costing.doc_no` is never assigned by any code found (21 of 21 rows NULL in ddtsdi, a unique index exists); `doc_date` comes from the DB default.
- What is blocked after Submit / Publish: `readOnly` (PENDING_APPROVAL, PUBLISHED, CANCELLED, `app/Services/Costing/CostingEntryService.php:41,66-74`). Since 2026-10-21 every mutator of `CostingEntryService` (updatePart, updateTier, updateHeader, updateCoating, addCoating, removeCoating, addPart, removePart, addPartFromInquiry, toggleDataSource, pickLayoutGroup) refuses on the server when the costing is not editable, and the route `routes/v2_procost.php` skips `ProCost::save` for a locked costing. `hitung` is still not guarded: `CostingEngine::run` always writes `doc_status = CALCULATED` (`app/Services/Costing/CostingEngine.php:59`) but never touches `published_flag`, so a direct POST with action hitung on a PUBLISHED costing would change the stored price columns and the status while `stat_confirm_procost` and Quotation availability (both follow `published_flag`) stay on (not tested; the Calculate button is disabled in the UI). There is no reject or back-to-draft path out of PENDING_APPROVAL in the code, and Publish exists only on the Inquiry screen, so an Instant document confirmed to PENDING_APPROVAL has no publish route unless it was reversed before.
- State log and history: `iqp_costing_state_log` has 0 rows in ddtsdi and no code writes it (only the relation `IqpCosting::stateLogs` exists, `app/Models/Sdi/IqpCosting.php:109-112`, with no caller); Pro-Cost does not write `doc_state_log` either. The only trace of Publish is `approved_by` / `approved_at` on `iqp_costing`; Submit to Direksi writes no actor (`app/Services/Costing/CostingEntryService.php:440-446`, `updated_by` not set). The listener behind `stat_confirm_procost` fires for model saves only; the header updates of `ppn_pct`, `ppn_mode` and `calc_notes` (`app/Services/Costing/CostingEntryService.php:409-417`) are plain model or query updates that may not fire it do not fire it, which is harmless because only `published_flag` matters.
- What is deleted when: Remove part deletes the coatings and the part but NOT its `iqp_costing_recommendation` rows, and that table has no foreign key (0 orphans in ddtsdi now; the Advisor history ignores costings that no longer exist, `app/Services/Costing/CostingAdvisor.php:335-346`). Applying a ProDev layout deletes the ESTIMATE recommendation rows of that part (`app/Services/Costing/CostingEntryService.php:180-207`). Deleting an Inquiry cascades `iqp_costing` and its parts, coatings, tiers and state log (foreign keys verified), but not `iqp_costing_recommendation`. The Instant Delete removes coatings, parts, tiers and the costing row one by one without a transaction.
