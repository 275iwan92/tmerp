# Concept card: Customer Order (CO)

> Written 2026-10-16 (group A). "FACT" = seen first-hand in this session: mockup DB (connection `tm2*` with `--env=mockup` = schema `ddt*`; row counts = `count(*)` today) and code with line numbers. "FROM DOCUMENT" = not checked against code/DB.

- **Document type**: concept card. **Module/sub-module**: Sales > Order > Customer Order (`sys_app_menu` code `SALES_SO`, target `v2:customer-order`, FACT).
- **Canonical name**: Customer Order = `tm2sdi.co_order` (header) + `co_order_item` (lines) + `co_order_delivery` (delivery schedule, see the CPDEL card) + `co_order_external_cost` (external costs).
- **Synonyms**: CO, SO, Sales Order, customer order, `co_no` (`CO2600059`), incoming order. The `co_order_legacy*` tables = archive of the old system, NOT new COs.
- **NOT the same as**: Quotation (`quo_quotation`, the offer), CPDEL (delivery schedule, separate card), Delivery Order (`do_delivery`, the physical delivery document).

## Findings (recorded, not fixed)
1. **CO2600021 (id 774) is inconsistent**: `doc_status=CONFIRMED` but `stat_cancel=1`, `cancel_reason` "Product has no Master Card (dummy data removed)". Its delivery schedule (id 1163) is still PLANNED and already has `posted_at`. `CoOrderBuilder::cancel` should have set `CANCELLED` and cancelled the schedule. Result: CPDEL (`Cpdel.php:42` filters `doc_status=CONFIRMED`) still shows it; Customer 360 (`Crm.php:44` filters `stat_cancel=0`) treats it as cancelled. FACT.
2. **Two words for cancelled**: `doc_status=CANCELLED` and `stat_cancel` are written together by `cancel`, but `REJECTED` only fills `doc_status` and `cancel_reason` (the rejection reason goes into the cancel reason column). Readers that only filter `stat_cancel=0` (`Crm.php:44,112`, `CrmComplaints.php:63`) do not exclude REJECTED COs. FACT (code); impact on figures not calculated.
3. **The v1 path skips approval**: `CoOrderBuilder::confirm` from DRAFT is called directly by `resources/views/pages/co/entry.blade.php:414` and `list.blade.php:180`; the v1 routes `/co`, `/co/{order}/edit` are still registered (`routes/web.php:159-160`, middleware `module:SALES`). The menu points to v2, so it is reachable only by URL. Rule A.11 requires approval. FROM CODE; not tried in a browser.
4. **11 of 24 CONFIRMED COs have no approval trace** in `flow_log` (module CO); 12 `doc_id` in `flow_log` CO no longer exist in `co_order` (orphans). Dummy created by seeder (e.g. `PpicSeedDummy.php:82` fills `doc_status` directly). FACT (cross query `ddtmst.flow_log` x `ddtsdi.co_order`).
5. **`sales_person_id` is empty in 25 of 25 COs.** INTEGRATED: `resolveSalesPerson` matches the text `iqp_inquiry.pic_sales` to `sales_person.sales_name`; the most frequent value "Firman" (17 inquiries) is not in the master (5 rows). INSTANT: `createInstant` does not fill it. FACT.
6. **Ship-to address is empty in 13 of 13 INTEGRATED COs**: `findOrCreateFromQuotation` does not copy the address; only `createInstant` copies `default_address` (`CoOrderBuilder.php:45-60` vs `143-145`). FACT.
7. **No Closed cycle exists** for CO (A.12): `STATUS_TONES` has only DRAFT, SUBMITTED, CONFIRMED, REJECTED, CANCELLED (`CustomerOrder.php:25`); the table has no `stat_close`. FACT (code).
8. **Status column naming**: the CLAUDE.md naming rule asks for `stat_confirm/stat_cancel/stat_close`; CO uses `doc_status` + `stat_cancel`. Also `doc_state_log`, mentioned in CLAUDE.md, does not exist in any DB (see the Status card). FACT.
9. **Delivery schedule quantity is not guarded**: `isConfirmable` does not check that the sum of `ship_qty` = line `qty`. In the mockup data: for all lines that have a schedule, the sum equals qty (0 exceptions). FACT (code and data).
10. **A.10 versus code**: the rule (`docs/globaluserrules.md:45`, short index, CLAUDE.md item 3b) says "14 hari kerja dari approval proof FISIK"; the code, the REMARK, migration `2026_10_16_000400`, and the description of constant `CO_LEAD_WORKDAYS` use ACC **Digital** ("Jo 2026-10-16"). One of them is outdated. Table `prod_product_acc` has types DIGITAL 2, EMAIL 2, SAMPLE 3; there is no FISIK type. FACT.
11. **`due_source='ACC'` is also used by INSTANT COs**, whose base is `co_date`, not ACC (`CoOrderItem.php:65,73`; data CO2600059). The value name is misleading. 24 old dummy rows are NULL (created before the migration). FACT.
12. Dummy `shipment_type` `DELIVER` (16 rows, `PpicSeedDummy.php:84`) is not in the screen choices FULL/PARTIAL (`customer-order.blade.php:141`). FACT.
13. There is no test for `CoOrderBuilder` (see the engine card); the existing CO tests are only `CoDueDateTest`, `CoListExpandRowTest`, `QtyMinimLumpSumTest`. FACT (grep).
