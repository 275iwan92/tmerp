# Sub-module: Quotation

> Group B, 2026-10-16. The sub-module page only summarizes and links. FACT = menu `sys_app_menu` mockup and code with lines.

- **Module**: Sales > Inquiry & Quotation. Menu (FACT): item `Quotation` (`v2:quotation`, id 113) directly under the group "Inquiry & Quotation" (not a group of its own); group Report (id 1089): Open Quotations (`v2:quotation-outstanding`), Follow-up Quotation (`v2:quotation-followup`), Win-Rate Sales (`v2:sales-win-rate`; the same item also exists in Sales > CRM > Report, id 1194). Item "Inquiry Note" (id 931) is inactive.
- **Purpose**: Sales picks priced inquiries (costing PUBLISHED) of one customer, builds the offer, publishes it (PUBLISHED), follows up (follow-up), then WIN (CO is born) or LOST.
- **Hard rules**: Quotation MUST be integrated (A.1); 1 Quotation = 1 CO (A.4/A.10, unique index in the DB); CO may be direct (INSTANT) without Quotation (A.2); price only for those entitled (A.8-A.9).
- **Frozen zone**: Quotation is part of the vital flow (`docs/claude_vital_flows.md`).

## Relations
- **source**: Inquiry with costing PUBLISHED (card `../product-costing/11_card_procost-interface.md`), customer, Sales PIC.
- **used_by**: Customer Order (WIN; the CO card belongs to another group), Master Product (born at WIN), Win-Rate, Follow-up (`crm_activity`).
- **flags**: Quotation has no `stat_confirm_*`; its status is `doc_status` DRAFT/PUBLISHED/CANCELLED, WON/LOST are derived from the inquiry status.

## Cross-card findings (summary)
- The server does not enforce "must be integrated": a freeform line (FREEFORM) can create a quotation without an inquiry; 5 PUBLISHED quotations in the data have no line at all.
- Quotation does not use the price filter `canViewSalesPrice` (only the SALES module gate).
- Outdated source label `quo_activity` (the real table is `crm_activity`).

Notes for debugging
- The v2 Save is NOT atomic. `Quotation::save` replays the form through `QuotationEntryService`, one statement per field, per CC change and per line, with no transaction around it (`app/Support/V2/Data/Quotation.php:195-230`); an error half way leaves a partly saved Draft. Add free line and Confirm run this same Save first and then add the line or publish as a separate step (`routes/v2.php:535-558`), so a refused Confirm still keeps the saved Draft. Confirm only checks status DRAFT and that lines exist (`app/Support/V2/Data/Quotation.php:237-242`); nothing checks that a line has an inquiry (a free line has `source_type` FREEFORM, `app/Services/Sales/QuotationEntryService.php:150`).
- What locks: after PUBLISHED, Save, Add inquiry, Delete and Confirm are refused with 422 (`app/Support/V2/Data/Quotation.php:189`, `app/Support/V2/Data/Quotation.php:197`, `app/Support/V2/Data/Quotation.php:239`, `app/Support/V2/Data/Quotation.php:247`); the `QuotationEntryService` methods silently return instead (`app/Services/Sales/QuotationEntryService.php:97`, `app/Services/Sales/QuotationEntryService.php:190`). Cancel, LOST and WIN are only allowed on a published quotation that has no outcome yet (`app/Support/V2/Data/Quotation.php:258`, `app/Support/V2/Data/Quotation.php:264`, `app/Support/V2/Data/Quotation.php:271`).
- Status is not stored except DRAFT, PUBLISHED and CANCELLED in `quo_quotation.doc_status`. WON and LOST are derived from `iqp_inquiry.sub_state` of the quotation lines (`app/Models/Sdi/QuoQuotation.php:81-90`), so Mark LOST writes only `iqp_inquiry` and only for inquiries not yet CANCELLED, CONVERTED or LOST (`app/Services/Sales/QuotationEntryService.php:209-211`); `quo_quotation.updated_at` is not touched and the screen's "closed" date for LOST is read from `updated_at` (`app/Support/V2/Data/Quotation.php:51`). No code was found that sets an inquiry back from LOST.
- Delete of a Draft runs in ONE tm2sdi transaction: lines, CC, follow-ups, then the header (`app/Support/V2/Data/Quotation.php:248-253`). The foreign keys agree: lines, CC and `crm_activity` CASCADE from `quo_quotation`, and `co_order.quotation_id` is RESTRICT (checked in ddtsdi), so a quotation that already has a Customer Order cannot be deleted. Deleting an inquiry sets `quo_quotation_item.inquiry_id` to NULL (SET NULL). Inquiries come back to the picker when the Draft is deleted or the quotation is Cancelled (`app/Services/Sales/QuotationBuilder.php:48-51`).
- Create and Add inquiry: `createFromInquiries` and `applyInquiries` each run in ONE tm2sdi transaction, including the number `QUOyyNNNNN` (`lockForUpdate`, `app/Models/Sdi/QuoQuotation.php:113-125`). When the added inquiry belongs to another customer, ALL lines and CC of the Draft are deleted and the header is overwritten from the new customer (`app/Services/Sales/QuotationBuilder.php:112-117`). Tooling lines are created only the first time an inquiry is added to the quotation (`app/Services/Sales/QuotationBuilder.php:185-187`). A line is created only for a tier that has a price in a PUBLISHED costing (`app/Services/Sales/QuotationBuilder.php:154`).
- WIN is one tm2sdi transaction (`app/Services/Sales/CoOrderBuilder.php:42`) that calls `ProductMasterSync`, whose writes go to tm2mst in a SECOND transaction on another connection (`app/Services/Sales/ProductMasterSync.php:27`). The draft product (`ensureDraftProduct`, `app/Models/Sdi/IqpInquiry.php:132-152`) is created before that transaction and the artwork file copy (`app/Services/Sales/ProductMasterSync.php:170`) is on disk. A rollback of the tm2sdi transaction leaves the tm2mst rows and the copied files behind. The step is idempotent: an existing CO for the quotation is returned and nothing is written (`app/Services/Sales/CoOrderBuilder.php:33-37`); only PUBLISHED quotations pass (`app/Services/Sales/CoOrderBuilder.php:29-31`). The final `CoOrderItem::where(...)->update(['product_id' => ...])` is a mass update, so the model `saving` hook (due date) does not run for it (`app/Services/Sales/CoOrderBuilder.php:108`, `app/Models/Sdi/CoOrderItem.php:56-75`); what that means for `due_date` of lines whose inquiry had no product yet was not traced.
- The Follow-up Quotation report lists every row of `crm_activity`, not only those with a quotation: `QuoActivity` has no scope and the query has no `quotation_id` filter (`app/Support/V2/Data/Quotation.php:92`, `app/Models/Sdi/QuoActivity.php:11-24`). In ddtsdi 9 of 15 rows have no quotation (query 2026-10-18), so those rows show an empty quotation number. The delete of a follow-up from the Quotation form silently does nothing for a row created by someone else (`app/Services/Sales/QuotationEntryService.php:238`).
- Not checked: the Email button of the form (only the Print route was read; no mail code opened); `x-dl::form` and `x-dl::lines` components; the price columns (not read on purpose); access beyond the route group `module:SALES` (`routes/v2.php:521`); the retired v1 chooser window markup; the v2 Customer Order and `CoEntryService` beyond the call into WIN; the Order and Master Product sub-modules' own processes; dummy builders (`app/Support/Dummy/StageBuilder.php:337-339` call Confirm and WIN, their other writes are not mapped); the stale label quo_activity in the report sources (text only, `resources/views/v2/screens/quotation-followup.blade.php:15`).
