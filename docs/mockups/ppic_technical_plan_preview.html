Technical Plan: PPIC Scheduling Module

GUIDE · PROD

Technical plan for PPIC: Work Orders come from Product Development data, and engines prepare material readiness, estimates and a draft schedule automatically. The officer confirms the plan and can give a job priority.Rencana teknis PPIC: Work Order berasal dari data Product Development, dan engine menyiapkan kesiapan bahan, perkiraan dan draf jadwal secara otomatis. Officer mengonfirmasi rencana dan dapat memberi prioritas pada job.

  1. Operating model (decided): Work Orders are created from ProDev data (BOP, routing, BOM). Material readiness (MRP), target estimates and the schedule are prepared automatically by engines. The officer confirms the plan and can give a job priority.Model kerja (diputuskan): Work Order dibuat dari data ProDev (BOP, routing, BOM). Kesiapan bahan (MRP), perkiraan target dan jadwal disiapkan otomatis oleh engine. Officer mengonfirmasi rencana dan dapat memberi prioritas pada job.
  2. Screen: one Production Scheduling screen with four views (Gantt, Kanban, Calendar, Grid), filtered by process and machine, showing setup time, gates and an exception list first, plus a Monitoring tab.Layar: satu layar Production Scheduling dengan empat tampilan (Gantt, Kanban, Calendar, Grid), difilter per proses dan mesin, menampilkan setup time, gerbang dan daftar pengecualian lebih dulu, plus tab Monitoring.
  3. Built on what exists: WoGenerationService, MaterialPlanningEngine, SpeedTargetEngine, PdrEngine, CompositePriorityScorer, SchedulingRuleEngine, the changeover table and the DevLib objects.Dibangun di atas yang sudah ada: WoGenerationService, MaterialPlanningEngine, SpeedTargetEngine, PdrEngine, CompositePriorityScorer, SchedulingRuleEngine, tabel changeover dan objek DevLib.
  4. New: AutoPlanRunner (runs the chain), tooling master, setup time engine, waste allowance cascade, readiness gates, capacity load, learning engine, monitoring service and the v2 screen with DevLib extensions.Baru: AutoPlanRunner (menjalankan rantai), master tooling, engine setup time, kaskade toleransi waste, gerbang kesiapan, beban kapasitas, engine pembelajar, service monitoring dan layar v2 dengan perluasan DevLib.
  5. Principles: engines prepare and log every change; nothing becomes the real schedule without the officer's Confirm; an engine never moves a locked task; no foreign keys across databases; every value has an input screen.Prinsip: engine menyiapkan dan mencatat tiap perubahan; tidak ada yang menjadi jadwal nyata tanpa Confirm officer; engine tidak pernah memindahkan task terkunci; tanpa foreign key lintas database; setiap nilai punya layar input.
  6. Confirmation: the engine runs by itself and produces a plan marked Draft. The officer reviews the exceptions and confirms; only a confirmed plan becomes the real schedule. Bookings are confirmed automatically when stock fully covers the need.Konfirmasi: engine berjalan sendiri dan menghasilkan rencana berstatus Draft. Officer meninjau pengecualian dan mengonfirmasi; hanya rencana terkonfirmasi yang menjadi jadwal nyata. Booking dikonfirmasi otomatis bila stok mencukupi seluruh kebutuhan.
  7. Frozen zone: Inquiry, ProDev and ProCost are not touched. PPIC only reads the BOP, routing and BOM they produce. Delivery is in six phases, each reviewed by the user.Zona beku: Inquiry, ProDev dan ProCost tidak disentuh. PPIC hanya membaca BOP, routing dan BOM yang mereka hasilkan. Pengerjaan dalam enam fase, tiap fase ditinjau user.

Technical Plan: PPIC Menu and Access

GUIDE · PROD

Where the screens sit in the Production menu and which access flags separate the scheduling officer from the inventory control officer.Letak layar di menu Production dan flag akses yang memisahkan officer penjadwalan dari officer pengendalian inventori.

  1. Production Scheduling (new, v2) replaces the old Scheduling Board as the daily screen. The old v1 board stays reachable until the user retires it.Production Scheduling (baru, v2) menggantikan Scheduling Board lama sebagai layar harian. Board v1 tetap bisa dibuka sampai user menghentikannya.
  2. Inside the screen, four page tabs: Schedule, Material Control (links to Material Planning and Material Booking), Incoming Purchases, Monitoring.Di dalam layar ada empat tab halaman: Schedule, Material Control (tautan ke Material Planning dan Material Booking), Incoming Purchases, Monitoring.
  3. New master screens: Tooling Master, Setup and Changeover Table, Waste Allowance (per process and machine), Learning Proposals. Customer Tier is a field in the Customer master, kept by Sales.Layar master baru: Master Tooling, Tabel Setup dan Changeover, Toleransi Waste (per proses dan mesin), Usulan Pembelajaran. Tier Customer adalah field di master Customer, dirawat Sales.
  4. Access flags, not new modules: PPIC_SCHEDULING changes queues and locks; PPIC_INVENTORY changes bookings, shortage follow-up and ready dates. Both read everything. One user can hold both.Flag akses, bukan modul baru: PPIC_SCHEDULING mengubah antrean dan kunci; PPIC_INVENTORY mengubah booking, tindak lanjut kekurangan dan tanggal siap. Keduanya membaca semuanya. Satu user boleh memegang keduanya.
  5. Menu rows are added by a migration into sys_app_menu (target v2:production-scheduling and so on), run first on the dummy menu database, then on live at release. Screens start as NOT_BUILT; only the user sets LOCKED.Baris menu ditambah lewat migration ke sys_app_menu (target v2:production-scheduling dan seterusnya), dijalankan dulu di database menu dummy, lalu di live saat rilis. Layar mulai NOT_BUILT; hanya user yang mengisi LOCKED.

Technical Plan: Scheduling Screen Design

GUIDE · PROD

How the one scheduling screen is assembled from DevLib objects so that the four views share the same data, filters and rules.Cara satu layar penjadwalan disusun dari objek DevLib agar empat tampilan memakai data, filter dan aturan yang sama.

  1. The screen opens with a Draft banner and an exception strip: time of the last auto-plan, operations planned, what needs a person (late risk, material waiting, tooling blocked, overload) and a Confirm plan button.Layar dibuka dengan banner Draft dan strip pengecualian: waktu auto-plan terakhir, operasi yang dijadwalkan, yang butuh manusia (berisiko telat, bahan menunggu, tooling terblokir, kelebihan beban) dan tombol Confirm plan.
  2. The screen file is thin: it hands one array from a data class (ProductionSchedule) to the objects. No raw HTML, as required for v2 screens.Berkas layar tipis: hanya menyerahkan satu array dari kelas data (ProductionSchedule) ke objek. Tanpa HTML mentah, sesuai aturan layar v2.
  3. One query builds the operations list for the chosen period, processes and machines. Gantt, Kanban, Calendar and Grid are four projections of that list, so a filter change updates all four.Satu query membangun daftar operasi untuk periode, proses dan mesin terpilih. Gantt, Kanban, Calendar dan Grid adalah empat proyeksi dari daftar itu, jadi perubahan filter memperbarui keempatnya.
  4. Objects: x-dl::gantt, x-dl::kanban, x-dl::calendar, x-dl::sheet for the views; x-dl::tabs for the page tabs; x-dl::drawer for the work order panel; x-dl::kpi for Monitoring.Objek: x-dl::gantt, x-dl::kanban, x-dl::calendar, x-dl::sheet untuk tampilan; x-dl::tabs untuk tab halaman; x-dl::drawer untuk panel work order; x-dl::kpi untuk Monitoring.
  5. Machine filter: a process lists its machines from prod_process_machine (preference rank, certified). Several machines per process are normal; the Gantt groups rows as process, then machine.Filter mesin: sebuah proses mendaftar mesinnya dari prod_process_machine (urutan preferensi, tersertifikasi). Banyak mesin per proses itu wajar; Gantt mengelompokkan baris proses lalu mesin.
  6. AutoPlanRunner fills a Draft. A manual move on the Gantt is a priority override: simulation first, checked by PdrEngine::validateManualReschedule, saved with a reason. Confirm plan makes the Draft real. Grid edits save in a batch.AutoPlanRunner mengisi Draft. Pemindahan manual di Gantt adalah penimpaan prioritas: simulasi dulu, dicek PdrEngine::validateManualReschedule, disimpan dengan alasan. Confirm plan membuat Draft menjadi nyata. Edit Grid disimpan sekaligus.
  7. Kanban moves are validated on the server: only Pending or Assigned cards may move; Running and Done may not. A refused move leaves the card where it was.Perpindahan Kanban divalidasi server: hanya kartu Pending atau Assigned yang boleh pindah; Running dan Done tidak. Pemindahan yang ditolak membiarkan kartu di tempatnya.
  8. The work order panel shows the setup breakdown, the routing table (target, waste, spoilage, setup per process), material lines with booking and incoming PO, and the output with a link to Production Output.Panel work order menampilkan rincian setup, tabel routing (target, waste, spoilage, setup per proses), baris bahan dengan booking dan PO datang, dan output dengan tautan ke Production Output.

Technical Plan: DevLib Work Needed First

GUIDE · PROD

Changes to DevLib objects the scheduling screen needs. DevLib is changed first, then the screen inherits, as the project rule requires.Perubahan objek DevLib yang dibutuhkan layar penjadwalan. DevLib diubah lebih dulu, lalu layar mewarisinya, sesuai aturan proyek.

  1. Gantt today shows the hours of one day. It needs a multi-day axis (days with hour ticks), grouping of rows by section (process), and a pixel-per-hour that fits the period.Gantt saat ini menampilkan jam dalam satu hari. Ia perlu sumbu multi hari (hari dengan tanda jam), pengelompokan baris per seksi (proses), dan piksel per jam yang sesuai periode.
  2. Gantt task gets a setup segment (hatched, minutes shown when wide enough), a progress strip, hot and lock icons, and three gate dots (material, tooling, artwork).Task Gantt mendapat segmen setup (bergaris, menit tampil bila cukup lebar), strip progres, ikon hot dan kunci, dan tiga titik gerbang (bahan, tooling, artwork).
  3. Gantt gets two vertical markers: Now and Locked until. Both are drawn over the rows only, never over the legend.Gantt mendapat dua penanda vertikal: Now dan Locked until. Keduanya digambar hanya di atas baris, tidak pernah di atas legenda.
  4. A view switch object (segmented control with icons) is added; today only the Gantt mode toggle looks similar. It keeps the chosen view and filters in the URL.Objek view switch (kontrol segmen dengan ikon) ditambahkan; saat ini hanya toggle mode Gantt yang mirip. Ia menyimpan tampilan dan filter terpilih di URL.
  5. Calendar gets a day cell with a load bar and a setup-hours line; Sheet gets a column flag for typed (yellow) against calculated (grey) cells.Calendar mendapat sel hari dengan bar beban dan baris jam setup; Sheet mendapat penanda kolom untuk sel diketik (kuning) lawan dihitung (abu).
  6. Each change lands in the DevLib package, is shown on devlib.test with a demo, and only then used by the screen. The catalog and Build board are refreshed with build:catalog.Tiap perubahan masuk ke paket DevLib, ditampilkan di devlib.test dengan demo, baru dipakai layar. Katalog dan papan Build diperbarui dengan build:catalog.

Technical Plan: PPIC Tables and Columns

GUIDE · PROD

Planned changes to tables, grouped by database. Names are English; relations across databases are logical and checked by Laravel, never by foreign keys.Perubahan tabel yang direncanakan, dikelompokkan per database. Nama dalam bahasa Inggris; relasi lintas database bersifat logis dan dicek Laravel, bukan foreign key.

  1. Every new table gets a single BIGINT auto-number primary key. Migrations mirror the live dump, run first on the dummy databases, and need user approval before any live schema change.Tiap tabel baru memakai satu primary key BIGINT auto number. Migration mencerminkan dump live, dijalankan dulu di database dummy, dan butuh persetujuan user sebelum mengubah skema live.
  2. prd_wo_operation has no process id and no setup columns today. Adding them lets the screen join to the process and machine rates and store the plan next to the actual.prd_wo_operation saat ini tidak punya id proses dan kolom setup. Menambahkannya memungkinkan layar menggabungkan ke tarif proses dan mesin dan menyimpan rencana di samping aktual.
  3. Existing columns are reused: waste and spoilage quantity on the operation, default waste and fixed waste on process and process-machine, target per hour on the part rate table, is_bottleneck on process.Kolom yang sudah ada dipakai ulang: qty waste dan spoilage di operasi, waste default dan waste tetap di proses dan proses-mesin, target per jam di tabel tarif part, is_bottleneck di proses.
  4. Values that can be learned carry a status (Assumed, Learning, Calibrated), a sample count and a freeze flag, so the learning engine knows what it may adjust.Nilai yang bisa dipelajari membawa status (Assumed, Learning, Calibrated), jumlah sampel dan flag bekukan, agar engine pembelajar tahu apa yang boleh disesuaikan.
  5. Scheduling settings (lock in shifts, weights, bottleneck threshold, learning limits) are rows in Settings > Constants, so every value has an input screen. Shift count per machine comes from the machine calendar.Pengaturan penjadwalan (kunci dalam shift, bobot, ambang bottleneck, batas pembelajaran) adalah baris di Settings > Constants, sehingga setiap nilai punya layar input. Jumlah shift per mesin berasal dari kalender mesin.

Code, type (plate set, cutting die, emboss die, foil die), product or dieline reference, size, location, status, planned and used impressions, setup minutes first run and repeat run.Baru. Kode, jenis (set plat, pisau pond, matras emboss, foil), referensi produk atau dieline, ukuran, lokasi, status, impresi rencana dan terpakai, menit setup run pertama dan run ulang.

tm2mst.prod_process_machineExists with setup minutes, speed, waste percent and fixed waste. tm2mst.prod_wait_ruleNew. Minimum wait in minutes after a process for a coating or ink kind before the next process (drying, curing).Baru. Waktu tunggu minimum dalam menit setelah sebuah proses untuk jenis coating atau tinta sebelum proses berikutnya (kering, curing).
tm2mst.cust_customerAdd customer tier (1 to 3, default 2). Kept in the Customer master by Sales.Tambah tier customer (1 sampai 3, default 2). Dirawat di master Customer oleh Sales.
tm2prd.prd_wo_operationAdd process id, base, changeover and tool setup minutes, target per hour, planned run minutes, plan status (DRAFT or CONFIRMED), locked flag and reason, planned by (ENGINE or OFFICER), actual setup minutes.Tambah id proses, menit setup dasar, changeover dan tooling, target per jam, menit jalan rencana, status rencana (DRAFT atau CONFIRMED), flag terkunci dan alasan, dijadwalkan oleh (ENGINE atau OFFICER), menit setup aktual.

tm2prd.prd_learning_proposalNew. Target table and row, field, old value, new value, sample count, basis, status (Proposed, Applied, Rejected, Reverted), decided by and at.Baru. Tabel dan baris sasaran, field, nilai lama, nilai baru, jumlah sampel, dasar, status (Proposed, Applied, Rejected, Reverted), diputuskan oleh dan pada.

Satu baris per auto-plan: waktu, pemicu (harian, awal shift, kejadian), operasi yang dijadwalkan, pengecualian yang ditemukan, durasi, dan siapa yang mengonfirmasi serta kapan.

Technical Plan: Engines and Services

GUIDE · PROD

Which engines and services are extended and which are new. All are registered in the engine catalog, and logic stays out of the screen.Engine dan service mana yang diperluas dan mana yang baru. Semuanya didaftarkan di katalog engine, dan logika tidak ada di layar.

  1. Every new engine gets an entry in EngineRegistry (purpose, input, output, how it works) and the catalog is refreshed with engine:catalog. EngineCatalogTest guards it.Tiap engine baru mendapat entri di EngineRegistry (kegunaan, input, output, cara kerja) dan katalog diperbarui dengan engine:catalog. EngineCatalogTest menjaganya.
  2. Each engine has regression tests against the real local MySQL database; tests that insert data clean up after themselves and the cleanup is verified in the database.Tiap engine punya test regresi terhadap database MySQL lokal sungguhan; test yang menyisipkan data membersihkan sendiri dan pembersihannya diverifikasi di database.
  3. Engines that calculate (setup, waste, load, readiness) are pure. AutoPlanRunner only writes Draft plans. The real schedule changes only when the officer confirms; the confirm and every change go to the decision log.Engine penghitung (setup, waste, beban, kesiapan) bersifat murni. AutoPlanRunner hanya menulis rencana Draft. Jadwal nyata berubah hanya saat officer mengonfirmasi; konfirmasi dan setiap perubahan masuk log keputusan.
AutoPlanRunner (new)Runs the chain and produces a Draft plan: check Work Orders, MRP and gates, estimates, schedule, exception list. Triggers: daily, start of each shift and events (new Work Order, material arrival, breakdown, officer priority).Menjalankan rantai dan menghasilkan rencana Draft: cek Work Order, MRP dan gerbang, perkiraan, jadwal, daftar pengecualian. Pemicu: harian, awal tiap shift dan kejadian (Work Order baru, bahan datang, kerusakan, prioritas officer).
WoGenerationService (extend)Already creates one Work Order per part from the delivery plan. Extend: store process id on each operation, fill start quantity from the waste cascade, copy BOM lines, flag a part without routing.Sudah membuat satu Work Order per part dari rencana kirim. Perluas: simpan id proses pada tiap operasi, isi jumlah awal dari kaskade waste, salin baris BOM, tandai part tanpa routing.
SpeedTargetEngine (reuse)Gives the estimated target per hour for every operation: machine history first, then model specification, then the process default. Replaces typing the target by hand.Memberi perkiraan target per jam untuk setiap operasi: riwayat mesin dulu, lalu spesifikasi model, lalu default proses. Menggantikan pengetikan target manual.
MaterialPlanningEngine (reuse)Runs daily and on demand: nets stock, booking and incoming purchases per Work Order, proposes bookings and purchase requests. GateService reads its result as the material gate.Berjalan harian dan sesuai permintaan: menetralkan stok, booking dan pembelian yang datang per Work Order, mengusulkan booking dan purchase request. GateService membaca hasilnya sebagai gerbang bahan.
SetupTimeEngine (new)Setup between two jobs on a machine = base setup + changeover (ink, ink type, substrate, size, plate, die) + tool setup. Returns minutes, extra waste and the breakdown for display.Setup antara dua job di satu mesin = setup dasar + changeover (tinta, jenis tinta, bahan, ukuran, plat, pisau) + setup tooling. Mengembalikan menit, waste tambahan dan rincian untuk tampilan.
GateService (new)Material, tooling, artwork, customer goods and capacity gate per operation: Ready, Waiting with date, or Blocked with reason. Reads Booking, Material Planning incoming, tooling status and proof approval.Gerbang bahan, tooling, artwork, barang titipan dan kapasitas per operasi: Ready, Waiting dengan tanggal, atau Blocked dengan alasan. Membaca Booking, incoming Material Planning, status tooling dan persetujuan proof.
CompositePriorityScorer (extend)Keeps Hot, Critical Ratio and due date layers. Adds customer tier, ageing and the setup-aware score inside the layer 2 window. Slack uses the whole remaining routing.Mempertahankan lapisan Hot, Critical Ratio dan due date. Menambah tier customer, ageing dan skor sadar setup di dalam jendela lapis 2. Slack memakai seluruh sisa routing.
SchedulingRuleEngine (extend)Sequencing rules as data: group by ink set, substrate, size and die. Smooths order only among tasks of equal priority.Aturan urutan sebagai data: kelompokkan menurut set tinta, bahan, ukuran dan pisau. Menghaluskan urutan hanya di antara task berprioritas setara.
PdrEngine (extend)Backward scheduling adds waits from prod_wait_rule, queue time, and picks among the machines of a process by preference rank and load.Penjadwalan mundur menambah tunggu dari prod_wait_rule, waktu antrean, dan memilih di antara mesin sebuah proses menurut urutan preferensi dan beban.
CapacityLoadService (new)Load per machine group = planned hours (incl. setup) over available hours after shifts, holidays and maintenance orders. Flags the bottleneck above the threshold.Beban per grup mesin = jam rencana (termasuk setup) dibagi jam tersedia setelah shift, libur dan order perawatan. Menandai bottleneck di atas ambang.
WasteAllowanceService (new)Backward cascade from finished quantity through the routing: input = output over (1 minus variable percent) plus fixed. Used by work order generation and Material Planning.Kaskade mundur dari jumlah jadi melalui routing: input = output dibagi (1 dikurangi persen variabel) ditambah tetap. Dipakai pembuatan work order dan Material Planning.
LearningEngine (new)Reads setup log and production output, proposes corrected values with status and sample count. Same pattern as SpeedTargetEngine and SpeedSuggestionStore.Membaca log setup dan output produksi, mengusulkan nilai terkoreksi dengan status dan jumlah sampel. Pola sama dengan SpeedTargetEngine dan SpeedSuggestionStore.
MonitoringService (new)Planned against actual per operation: finish, good output, waste, setup minutes, material used against issued, late reason. Feeds the KPIs and the learning engine.Rencana lawan aktual per operasi: selesai, hasil baik, waste, menit setup, bahan terpakai lawan keluar, alasan telat. Menyuplai KPI dan engine pembelajar.

Technical Plan: PPIC Data Flow

GUIDE · PROD

How data moves from a confirmed Customer Order to a scheduled operation, to actual results, and back into the assumed values.Bagaimana data mengalir dari Customer Order terkonfirmasi ke operasi terjadwal, ke hasil aktual, dan kembali memperbaiki nilai asumsi.

  1. Delivery plan posted from a confirmed Customer Order: WoGenerationService creates one Work Order per part, with operations from the BOP and routing and material lines from the BOM. Process id is stored.Rencana kirim dari Customer Order terkonfirmasi diposting: WoGenerationService membuat satu Work Order per part, dengan operasi dari BOP dan routing dan baris bahan dari BOM. Id proses disimpan.
  2. Estimates, automatic: WasteAllowanceService sets the start quantity, SpeedTargetEngine the target per hour, SetupTimeEngine the setup minutes of each operation.Perkiraan, otomatis: WasteAllowanceService menentukan jumlah awal, SpeedTargetEngine target per jam, SetupTimeEngine menit setup tiap operasi.
  3. Material readiness, automatic: MaterialPlanningEngine nets stock, booking and incoming purchases and proposes bookings and purchase requests; GateService marks each operation Ready, Waiting or Blocked.Kesiapan bahan, otomatis: MaterialPlanningEngine menetralkan stok, booking dan pembelian yang datang dan mengusulkan booking dan purchase request; GateService menandai tiap operasi Ready, Waiting atau Blocked.
  4. AutoPlanRunner schedules the Ready operations as a Draft plan: priority score, backward scheduling with waits, machine choice among the process machines. It never touches the confirmed, locked window.AutoPlanRunner menjadwalkan operasi yang Ready sebagai rencana Draft: skor prioritas, penjadwalan mundur dengan waktu tunggu, pemilihan mesin di antara mesin proses. Ia tidak pernah menyentuh jendela terkonfirmasi yang terkunci.
  5. The officer reviews the exceptions (late risk, material waiting, tooling blocked, overload), may give a job priority (Hot or move up, with a reason), then confirms. Confirm writes the real start and finish and locks the first shifts.Officer meninjau pengecualian (berisiko telat, bahan menunggu, tooling terblokir, kelebihan beban), boleh memberi prioritas pada job (Hot atau naikkan, dengan alasan), lalu mengonfirmasi. Confirm menulis mulai dan selesai nyata dan mengunci shift pertama.
  6. Shop floor records output, defects and actual setup minutes. MonitoringService compares plan and actual; LearningEngine corrects the assumed values inside its limits and logs each change.Lantai produksi mencatat output, cacat dan menit setup aktual. MonitoringService membandingkan rencana dan aktual; LearningEngine mengoreksi nilai asumsi dalam batasnya dan mencatat tiap perubahan.

Technical Plan: PPIC Rules and Formulas

GUIDE · PROD

The formulas and rules the engines implement, with start values that live in Settings > Constants.Rumus dan aturan yang diimplementasikan engine, dengan nilai awal yang tersimpan di Settings > Constants.

  1. Remaining work = sum over remaining operations of setup, run time, queue and waits. Slack = (due date minus now) minus remaining work. Critical Ratio = (due date minus now) divided by remaining work.Sisa pekerjaan = jumlah semua operasi tersisa dari setup, waktu jalan, antrean dan tunggu. Slack = (due date dikurangi sekarang) dikurangi sisa pekerjaan. Critical Ratio = (due date dikurangi sekarang) dibagi sisa pekerjaan.
  2. Layers: 0 Hot; 1 Critical Ratio below 1; 2 normal. Inside layer 2, jobs whose slack differs by less than the window (default one shift) are ranked by the setup-aware score.Lapisan: 0 Hot; 1 Critical Ratio di bawah 1; 2 normal. Di dalam lapis 2, job yang selisih slack-nya kurang dari jendela (default satu shift) diurutkan dengan skor sadar setup.
  3. Score = Wdue x urgency + Wsetup x (1 minus setup / longest setup) + Wcust x tier + Wage x age, each 0 to 1; defaults 0.50, 0.35, 0.15 and a small ageing weight. Stored as constants.Skor = Wdue x urgensi + Wsetup x (1 dikurangi setup / setup terpanjang) + Wcust x tier + Wage x umur, tiap nilai 0 sampai 1; default 0,50, 0,35, 0,15 dan bobot ageing kecil. Disimpan sebagai konstanta.
  4. Setup = base + changeover + tool. Total job setup counts as non-productive time in the load and the dates. A job is never delayed by setup savings for longer than one lock period.Setup = dasar + changeover + tooling. Total setup job dihitung sebagai waktu tidak produktif pada beban dan tanggal. Job tidak pernah ditunda penghematan setup lebih dari satu masa kunci.
  5. Waste cascade: input = output / (1 - variable percent) + fixed, from the last process back to the first. Material to issue = first input. Rounded up to whole units.Kaskade waste: input = output / (1 - persen variabel) + tetap, dari proses terakhir mundur ke yang pertama. Bahan yang dikeluarkan = input pertama. Dibulatkan ke atas ke satuan utuh.
  6. Load = planned hours incl. setup / available hours. Bottleneck when the load is at least the threshold (default 90 percent) and the highest of its horizon; the process flag is_bottleneck is the manual override.Beban = jam rencana termasuk setup / jam tersedia. Bottleneck bila beban minimal ambang (default 90 persen) dan tertinggi di horizonnya; flag is_bottleneck pada proses adalah penimpaan manual.
  7. Learning: typical actual = median of the last N jobs (default 5, extremes ignored). New value = old + alpha x (typical minus old), alpha default 0.3, step limited to 20 percent. Frozen values are skipped.Pembelajaran: aktual tipikal = median N job terakhir (default 5, ekstrem diabaikan). Nilai baru = lama + alpha x (tipikal dikurangi lama), alpha default 0,3, langkah dibatasi 20 persen. Nilai beku dilewati.
  8. Auto-plan runs daily, at shift start and on events and makes a Draft; the officer's Confirm makes it real. Lock = the next N running shifts (N set by the officer, default 1). Engines never move locked tasks; breaking the lock needs a reason.Auto-plan berjalan harian, tiap awal shift dan saat kejadian dan membuat Draft; Confirm officer membuatnya nyata. Kunci = N shift berjalan berikutnya (N diatur officer, default 1). Engine tidak memindahkan task terkunci; membuka kunci butuh alasan.
